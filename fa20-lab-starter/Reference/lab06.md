## 练习 1：处处都是低效

假设寄存器初值为 0。打开 `exercise1.circ` 中的 `non_pipelined` 子电路：两个输入相乘，结果加到当前状态值上。

时序参数：

| 元件 | 延迟 |
|---|---|
| 加法器 | 45 ns |
| 乘法器 | 60 ns |
| 寄存器 CLK-to-Q | 10 ns |
| 寄存器 setup time | 10 ns |
| 寄存器 hold time | 5 ns |

**计算该电路能运行的最高时钟频率。** 假设两个输入都来自接收外部数据的时钟寄存器。

### 要点

- 关键路径（critical path）= 一个时钟周期内信号必须稳定的最长组合路径。
- 周期 = CLK-to-Q + 最长组合延迟 + setup time（hold time 影响的是"最短路径"，不决定最高频率）。
- 非流水线：`10 + 60 + 45 + 10 = 125 ns` → **最高频率 = 1/125ns = 8 MHz**。
- 准备向 TA 展示计算过程。

## 练习 2：流水起来

把电路改成两级流水：先乘法、后加法，以提高时钟频率。

判定"正确"的标准：流水线输出序列等于非流水线输出序列，只允许前面多出若干 0。例如非流水线输出 `[3, 5, 1, 2, 4, …]`，流水线输出 `[0, 3, 5, 1, 2, 4, …]` 也算正确。可用 `Simulate` 菜单手动打拍或开启连续 tick 验证。

`exercise1.circ` 的主电路已配置好非流水线输出序列 `[3, 5, 1, 2, 4, -1, 0, 0, …]`。ROM 应已初始化好输入；若出错，选中 ROM → `Contents` → `Open` → 选 `Romdata`。

> 流水线需要在两级之间加一个寄存器保存中间结果——这是流水线的通用做法。

### 任务

- 完成 `pipelined` 子电路：加一个寄存器，把乘法级与加法级分开。
- 计算你搭出的流水线电路的**最高时钟频率**。
- 讨论：若一个计算依赖前一个计算的结果，通常很难直接流水，需要插入一个或多个"气泡（bubble）"（故意延迟指令）。**解释为什么本电路不需要任何气泡。**

### 要点

- 流水线周期 = CLK-to-Q + **最长一级**的组合延迟 + setup time。
  - 乘法级：`10 + 60 + 10 = 80 ns`；加法级：`10 + 45 + 10 = 65 ns`。
  - 取最大者 80 ns → **最高频率 = 1/80ns = 12.5 MHz**。
- 为什么不需要气泡：每个周期都有来自外部时钟寄存器的新输入，乘法与加法都是固定延迟；上一周期的乘法结果在流水线寄存器里等一个周期后正好供加法级使用，数据依赖由"寄存器延迟一拍"自然解决，不存在需要等待或结构性冲突的情况。
- 准备展示：流水线电路、时钟频率计算、无气泡的理由。
